# 🩺 MIS Dash

MIS Dash (`mis_dash`) — прототип веб-дашборда для просмотра объёмной истории
пациента из медицинской информационной системы.

В медицинской информационной системе хранится история пациента: врачебные
приёмы, диагнозы, назначения, результаты анализов, операции и аллергии. За годы
наблюдения она превращается в сотни записей, тогда как время амбулаторного
приёма ограничено. MIS Dash помогает быстро выделить основные сведения и
проследить динамику показателей, не заставляя интерфейс зависеть от структуры
исходной выгрузки.

На вход приложение принимает «грязный» JSON-файл МИС объёмом около 250 тысяч
строк. Parser нормализует неполные и неоднородные данные, backend формирует
стабильный контракт, а Streamlit-интерфейс показывает профиль пациента,
временные ряды, историю приёмов и вызываемую по запросу ИИ-сводку.

Проект создаётся в учебных целях и работает с синтетическими данными. Пациент
в тестовой выгрузке вымышлен, однако структура файла воспроизводит характерные
проблемы реальных экспортов: разные форматы дат и чисел, опечатки в ключах,
пропущенные блоки, свободный медицинский текст и дубликаты.

## Основные термины

- **МИС / MIS (Medical Information System)** — медицинская информационная
  система, в которой учреждения ведут данные пациентов и рабочие процессы.
- **ЭМК / EHR (Electronic Health Record)** — электронная медицинская карта:
  история состояний, обследований, приёмов и лечения пациента.
- **Красные флаги / red flags (`red_flags`)** — объяснимые сигналы о
  потенциально важных фактах или отклонениях, которые требуют внимания
  специалиста. Это не диагнозы и не автоматические медицинские рекомендации.
  Интерфейс уже поддерживает такие сигналы, но модуль правил пока не реализован.

## Быстрый старт

Требуется Python 3.10 или новее.

1. Склонируйте репозиторий:

   ```bash
   git clone https://github.com/rsul07/mis_dash.git
   cd mis_dash
   ```

2. Создайте и активируйте виртуальное окружение:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   ```

3. Установите зависимости и создайте локальную конфигурацию:

   ```bash
   pip install -r requirements.txt
   cp .env.example .env
   ```

   Для ИИ-сводки укажите в `.env` собственный `GEMINI_API_KEY`. Ключ
   необязателен для остальных функций приложения и не должен попадать в Git.
   `OUTPUT_DIR` управляет только сохранением через `MISParser.parse()` и не
   влияет на загруженные в Streamlit файлы.

4. Запустите тесты и приложение:

   ```bash
   pytest -q
   streamlit run src/app/main.py
   ```

5. Откройте адрес, показанный Streamlit, и загрузите
   `data/patient_etalon.json`.

Проверить ключ Gemini отдельно, не отправляя историю пациента, можно командой:

```bash
python -m src.summarizer.check
```

## Стек

- **Python 3.10+** — основной язык приложения и обработки данных;
- **Pydantic** — строгие версионированные контракты;
- **Streamlit** — веб-интерфейс;
- **Plotly** — интерактивные графики временных рядов;
- **Google Gemini API и `google-genai`** — структурированная ИИ-сводка по
  ограниченному медицинскому контексту;
- **pytest** — модульные и интеграционные тесты;
- **Typst и Mermaid** — отчёт и архитектурные диаграммы.

## Структура репозитория

```text
mis_dash/
├── data/                 # синтетическая эталонная выгрузка
├── docs/
│   ├── diagrams/         # общие Mermaid-исходники и SVG/PNG
│   └── report/           # Typst-отчёт и публичные шаблоны
├── src/
│   ├── app/              # Streamlit-интерфейс
│   ├── backend/          # построение DashboardResponse v1
│   ├── calculators/      # объяснимые медицинские формулы
│   ├── contracts/        # PatientRecord, DashboardResponse, ClinicalSummary
│   ├── parser/           # разбор и нормализация выгрузки МИС
│   ├── storage/          # чтение и атомарная запись PatientRecord
│   └── summarizer/       # контекст, Gemini-клиент и валидация сводки
├── tests/                # автоматизированные тесты
├── .env.example          # пример локальной конфигурации
└── requirements.txt      # Python-зависимости
```
