# Контроль качества generator → parser

`src/quality` запускает встроенный синтетический generator, передаёт грязный
JSON через публичную границу `MISParser` и формирует проверяемый отчёт. Это
регрессионный инструмент разработчика: он не участвует в runtime Streamlit и
не выставляет непрозрачный «процент качества».

Каждая проверка имеет стабильное имя, ожидаемое и фактическое значение,
короткое evidence и отдельный статус. Ошибка хотя бы одного обязательного
инварианта приводит к ненулевому exit code.

## Быстрый запуск

Матрица небольших выгрузок подходит для повседневной разработки:

```bash
python -m src.quality \
  --seeds 1 7 42 \
  --years 1 \
  --light \
  --format markdown
```

Полный эталонный сценарий:

```bash
python -m src.quality \
  --seeds 42 \
  --years 9 \
  --format markdown
```

Машиночитаемый отчёт можно сохранить в игнорируемую директорию данных:

```bash
python -m src.quality \
  --seeds 7 42 99 \
  --years 3 \
  --light \
  --format json \
  --out data/quality/parser-quality.json
```

Время выполнения включается в отчёт только для наблюдения. Жёсткого порога
производительности нет: он был бы нестабилен между разными компьютерами.

## Проверяемые инварианты

| Имя | Что доказывает |
| --- | --- |
| `parse.success` | JSON разобран и валидирован как `PatientRecord 1.0`. |
| `counts.encounters` | Явные `_dup`-копии учтены, число логических приёмов совпадает. |
| `counts.laboratory` | Число панелей и неудалённых именованных результатов совпадает. |
| `counts.instrumental` | Именованные инструментальные заключения не потеряны. |
| `counts.self_monitoring` | Валидные АД, ЧСС и глюкоза из дневника представлены ожидаемым числом наблюдений. |
| `canonical.ids_unique_by_type` | ID уникальны внутри каждого типизированного ресурса. |
| `references.integrity` | Связи приёмов, назначений, наблюдений и отчётов разрешаются в обе стороны. |
| `provenance.paths_resolve` | Каждый `source.path` существует в исходном JSON и согласован с `source.block`. |
| `provenance.source_ids_match` | `source_id` найден в указанной исходной записи или её родителе. |
| `laboratory.comments_preserved` | Предупреждения о гемолизе, хилёзе и повторном исследовании сохранены. |
| `values.numeric_finite` | В канонической записи нет `NaN` и бесконечностей. |
| `exclusions.intentional` | Служебные/миграционные блоки и удалённые результаты исключены явно. |
| `values.numeric_fidelity` | Лабораторные и дневниковые числа совпадают после независимого разбора десятичной записи. |
| `dates.supported_values_preserved` | Поддерживаемые даты приёмов, исследований и дневника сохраняют дату или точный момент времени. |

Проверки чисел и дат используют собственные небольшие функции чтения форматов,
а не вызывают normalizer parser. Это позволяет обнаружить регрессию в самом
normalizer, а не повторить её в ожидаемом результате.

Для `seed=42`, `years=9`, `light=False` текущий отчёт имеет статус `PASS`.

| Evidence | Значение |
| --- | ---: |
| Сырые / логические приёмы | 87 / 81 |
| Лабораторные панели / результаты | 1 416 / 6 293 |
| Инструментальные отчёты | 36 |
| Канонические наблюдения | 20 268 |
| Сверенные числовые значения | 25 147 |
| Сверенные даты | 16 457 |
| Разрешённые `source.path` | 22 195 |
| Сверенные `source_id` | 8 294 |
| Сохранённые лабораторные комментарии | 328 |

Эти числа — регрессионный ориентир одной фиксированной синтетической
конфигурации, а не ограничение `PatientRecord` и не характеристика реальных
пациентов.

## Границы проверки

- QA проверяет структурную полноту и точность преобразования данных,
  создаваемых текущим generator.
- Отдельные unit-тесты parser по-прежнему нужны для отсутствующих блоков,
  неверных типов и aliases, которых нет в конкретной сгенерированной выборке.
- Статус `PASS` не подтверждает клиническую корректность синтетической истории,
  медицинских рекомендаций или репрезентативность набора данных.
- При намеренном изменении сырой схемы сначала уточняется ожидаемая семантика,
  затем вместе обновляются generator, parser, инварианты, тесты и документация.
