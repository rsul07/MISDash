# Архитектурные диаграммы MIS Dash

`docs/diagrams` — единый источник архитектурных иллюстраций для технической
документации и презентации. Редактируемые Mermaid-исходники находятся в
`src/`, готовые SVG и PNG — в `rendered/`.

## Состав

- `system-architecture` — полная техническая схема: два источника JSON,
  модули, контракты и внешние системы MIS Dash;
- `system-architecture-presentation` — компактный поток «данные → обработка →
  результат» для слайда;
- `parser-components` — внутренняя структура parser;
- `processing-sequence` — полная последовательность обработки с внутренними
  сервисами;
- `processing-sequence-presentation` — два коротких пользовательских сценария:
  основной dashboard и необязательная ИИ-сводка.

Диаграмма системы намеренно использует реальные пути пакетов. `PatientRecord`,
`DashboardResponse` и `ClinicalSummary` обозначают Pydantic-контракты, а не
отдельные запущенные сервисы. Всё приложение, кроме внешнего Gemini API,
работает в одном Python-процессе Streamlit.

## Редактирование и сборка

Чтобы изменить подпись или элемент, отредактируйте соответствующий `.mmd` в
`src/`, затем из корня репозитория выполните:

```bash
docs/diagrams/render.sh system-architecture
```

Без аргумента скрипт пересобирает все диаграммы. После сборки нужно проверить
SVG или PNG визуально и добавить в коммит и исходник, и оба результата рендера.

Для технической документации используйте полную версию. Для слайда 16:9
выбирайте файл с суффиксом `-presentation`: в нём крупнее подписи и меньше
внутренних деталей.

## Использование

В Markdown предпочтителен SVG. Например, для файла, который лежит
непосредственно в `docs/`, ссылка выглядит так:

```markdown
![Архитектура MIS Dash](diagrams/rendered/system-architecture.svg)
```

Для презентации используйте PNG из `docs/diagrams/rendered/`, а в Markdown —
SVG. Отдельные копии диаграмм создавать не нужно.
