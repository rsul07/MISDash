# Синтетический генератор выгрузок МИС

`src/generator` создаёт намеренно «грязные» JSON-выгрузки для разработки и
демонстрации MIS Dash. В данных встречаются разные форматы дат и чисел,
пропуски, исторические имена полей, дубли, свободный текст и служебные блоки.
Это синтетика: генератор не читает реальные медицинские карты.

Пакет получен рефакторингом исходного однофайлового generator в небольшие
доменные модули. Прежний скрипт не является runtime-зависимостью: весь
необходимый код находится в `src/generator`, поэтому клона репозитория
достаточно для запуска, тестирования и генерации.

## Python API

```python
from src.generator import GenerationConfig, generate_json_bytes

config = GenerationConfig(seed=7, years=3, light=True)
file_bytes = generate_json_bytes(config)
```

Публичные функции:

- `generate_export(config)` — возвращает Python-словарь;
- `generate_json_bytes(config)` — возвращает форматированный UTF-8 JSON;
- `write_export(path, config)` — записывает JSON и возвращает
  `GenerationStats`.

`GenerationConfig` содержит:

- `seed` — целое число, определяющее воспроизводимую вариацию грязных форм;
- `years` — глубина истории от 1 до 30 лет;
- `light` — уменьшенное число приёмов, лабораторных заказов и
  инструментальных исследований.

Одинаковая конфигурация создаёт одинаковые байты независимо от локального
часового пояса: Unix timestamp формируется относительно UTC. Конфигурация
`seed=42`, `years=9`, `light=False` побайтово соответствует
`data/patient_etalon.json` и служит эталонным регрессионным примером.

## CLI

Из корня репозитория:

```bash
python -m src.generator \
  --seed 7 \
  --years 3 \
  --light \
  --out data/generated/patient_seed_7.json
```

Без аргументов используются `seed=42`, `years=9`, полный режим и файл
`patient_demo.json`. CLI создаёт родительскую директорию и выводит размер,
число строк, приёмов и лабораторных заказов.

## Интеграция с приложением

В Streamlit доступны два источника:

1. загрузка готового JSON;
2. создание синтетической выгрузки по `seed`, глубине истории и режиму.

Генерация выполняется только после отправки формы, результат хранится в
`st.session_state` и доступен для скачивания. В обоих случаях приложение
передаёт одинаковые JSON-байты в `src/app/data.py`, а затем через временный файл
в `MISParser.parse_record()`. У generator нет обходного пути к backend:
сгенерированный и загруженный файлы проходят одну parser boundary и один
`DashboardService`.

## Ограничения

- Все конфигурации описывают вариации истории одной фиксированной
  синтетической персоны, а не независимых пациентов.
- `light` сокращает приёмы и исследования, но не уменьшает плотность дневников
  самоконтроля АД и глюкозы. Поэтому многолетняя выгрузка даже в этом режиме
  остаётся объёмной.
- Сырой формат generator не является публичным контрактом приложения.
  Совместимость с ним локализована в `src/parser`; frontend использует только
  `DashboardResponse`.
