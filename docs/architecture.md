# Архитектура MIS Dash

MIS Dash — модульное Python-приложение, запускаемое одним процессом Streamlit.
Generator, parser, backend, калькуляторы и summarizer являются пакетами внутри
приложения, а не отдельными сетевыми сервисами. Единственная внешняя
runtime-зависимость на схеме — Gemini API, который вызывается только по явному
действию пользователя.

![Архитектура MIS Dash](diagrams/rendered/system-architecture.svg)

## Основной сценарий

Интерфейс принимает готовый файл или формирует синтетическую выгрузку:

```text
загруженный JSON ─────────────┐
                             ├─→ байты грязного JSON
src/generator → synthetic JSON┘
    → MISParser.parse_record()
    → PatientRecord 1.0
    → DashboardService.build()
    → DashboardResponse 1.1
    → компоненты Streamlit
```

`src/app/source.py` отвечает только за выбор источника. После этого обе ветви
проходят одну границу `src/app/data.py`: parser и backend выполняются один раз,
а оба валидированных результата кешируются по содержимому JSON. Временный файл
нужен только потому, что публичный интерфейс `MISParser` принимает путь;
`data.py` удаляет его сразу после разбора.

Опциональный файловый сценарий:

```text
MISParser.parse()
    → <output_dir>/patient_record.json
    → DashboardService.build_from_path()
```

Он полезен для отладки и повторной обработки канонической записи, но
Streamlit-приложение его не использует. `output_dir` выбирается из аргумента
конструктора, затем из `OUTPUT_DIR`, а при отсутствии обоих равен
`data/processed/`.

## Модули

| Путь | Роль | Основной публичный результат |
| --- | --- | --- |
| `src/generator` | воспроизводимая синтетическая грязная выгрузка | JSON-словарь или UTF-8 bytes |
| `src/contracts/patient/v1` | каноническая медицинская модель | `PatientRecord 1.0` |
| `src/parser` | tolerant reader и адаптер грязной выгрузки | `MISParser` |
| `src/quality` | developer-аудит generator → parser | именованные проверки и Markdown/JSON-отчёт |
| `src/storage` | строгая загрузка и атомарная запись | `patient_record.json` |
| `src/calculators` | чистые формулы, классификаторы и метаданные | `CalculatedValue` |
| `src/backend` | профиль, ряды, приёмы и связь входов формул | `DashboardResponse 1.1` |
| `src/contracts/dashboard/v1` | стабильная схема интерфейса | `DashboardResponse` |
| `src/summarizer` | ограничение контекста и Gemini-клиент | `ClinicalSummary` |
| `src/contracts/summarizer/v1` | structured output ИИ-сводки | `ClinicalSummary` |
| `src/app` | выбор источника, экраны и состояние Streamlit | веб-интерфейс |

## Направление зависимостей

- Контракты не импортируют parser, backend или UI.
- Generator не импортирует parser или backend и создаёт только сырой
  синтетический JSON.
- Parser знает исходные ключи МИС и создаёт только `PatientRecord`.
- Quality вызывает generator и публичный parser, но runtime-модули его не
  импортируют.
- `src/calculators` не читает `PatientRecord`; backend передаёт формулам
  проверенные примитивные значения.
- Backend не знает исходные ключи МИС и не изменяет каноническую запись.
- Детерминированные компоненты UI читают только `DashboardResponse`.
- Orchestrator ИИ-сводки получает также `PatientRecord`, но передаёт Gemini
  только ограниченные факты, а не исходную выгрузку или все наблюдения.

Эти правила позволяют менять адаптер входной МИС, формулы и представление
интерфейса независимо.

`src/generator` получен рефакторингом исходного однофайлового generator, но
runtime-реализация полностью находится внутри репозитория. Его параметры,
детерминизм и ограничения описаны в
[отдельной документации](generator.md).

`src/quality` находится вне runtime-потока. Это developer-инструмент, который
строит синтетические выгрузки, вызывает публичный `MISParser` и проверяет
именованные инварианты без изменения `PatientRecord`. Он не используется
frontend и не является отдельным сервисом. Подробнее:
[контроль качества parser](parser_quality.md).

## ИИ-контур

`SummaryService` не вызывается при загрузке файла. После нажатия кнопки
ИИ-контур:

1. выбирает последние текстовые приёмы и инструментальные заключения;
2. ограничивает размер каждого поля и всего контекста;
3. отправляет prompt и JSON Schema в Gemini;
4. валидирует ответ как `ClinicalSummary`;
5. удаляет пункты с неизвестными `source_ids`;
6. передаёт проверенную структуру в `src/app/summary.py`, где она форматируется
   и записывается в копию `DashboardResponse.ai_summary`.

Числовые формулы выполняются только детерминированным кодом. Structured output
гарантирует форму ответа, но не его медицинскую истинность.

## Текущие границы

- `red_flags` присутствует в backend-контракте и UI, но rules engine ещё не
  реализован;
- постоянной базы данных, API-сервера, аутентификации и deployment-конфигурации
  нет;
- `patient_record.json` — опциональный локальный артефакт, не база данных;
- process-wide cache Streamlit не рассматривается как безопасное хранилище
  реальных медицинских данных;
- generator создаёт вариации истории одной фиксированной синтетической
  персоны, а не независимую популяцию;
- Gemini Free Tier допускается только для синтетических данных проекта.
